# UI 문자열과 영문 리소스

애플리케이션의 258개 TypeScript/TSX 파일을 조사하고, UI에서 사용하는 문구를 `shared/i18n/en.ts`의 영문 메시지 4,104개로 분리했다. 기본 언어는 `en`이다. 동일한 영문이라도 문맥이 다르면 별도의 키를 유지한다.

## 파일과 사용법

- `shared/i18n/en.ts`: 메시지 원문. 키를 유지하면서 문구를 수정한다.
- `shared/i18n/resource.ts`: 원문과 번역 리소스의 컴파일 단계 검증.
- `shared/i18n/index.ts`: 메시지 키·인자 타입, 이름이 있는 값 치환, 복수형 선택.
- `shared/i18n/labels.ts`: 상태·역할·작업 코드의 표시 문구.
- `web/components/i18n.tsx`: 링크·강조·조건부 요소를 유지하는 `LocalizedMessage`.
- `scripts/audit-ui-strings.mjs`: 하드코딩된 UI 문구의 재유입 검사.

```tsx
t("common.save");
t("workspace.navigation", { name: appName });
plural("counts.items", count);
enumLabel(account.status);

<LocalizedMessage
  id="workspace.navigation"
  values={{ name: <strong>{appName}</strong> }}
/>;
```

메시지는 `{name}` 형태의 인자를 사용한다. 문자열 인자는 한 번만 치환하고 HTML로 해석하지 않는다. 링크와 같은 React 요소는 `LocalizedMessage`로 전달한다. 수량에 따라 달라지는 문구는 `.one`과 `.other`에 명사·문장 전체를 저장한다.

정적 `index.html`의 `{{i18n:...}}` 표시는 Vite가 개발·빌드 시 영문 메시지로 치환한다. 공개 캘린더 페이지는 같은 리소스를 사용하며, HTML 텍스트와 브라우저 스크립트에 맞게 각각 이스케이프한다. CSS 선택자는 번역되는 접근성 레이블에 의존하지 않는다.

## 리소스 타입 검사

영문 원문은 `defineMessages({...})`로 선언한다. 값은 리터럴 문자열이어야 하며, `{name}`의 이름은 영문·숫자·밑줄로 구성하고 숫자로 시작하지 않는다. 닫히지 않은 괄호·중첩된 괄호·빈 인자는 컴파일 오류다. `.one`과 `.other`는 짝을 이루고 같은 인자를 사용해야 하며, 두 문장 모두 `{count}`를 포함한다. `labels.*`는 인자가 없는 문구만 허용한다.

다른 언어 파일은 원문을 기준으로 `defineTranslations(en, {...})`로 선언한다.

```ts
import { en } from "./en.ts";
import { defineTranslations } from "./resource.ts";

export const ko = defineTranslations(en, {
  ...en,
  "workspace.navigation": "{name} 탐색",
});
```

위 예제는 한 문구만 바꾸고 나머지는 영문을 유지한다. 전체 사전을 작성하면 누락·추가된 키, 문자열 이외의 값, 잘못된 메시지 형식, 누락·추가·변경된 인자를 검사한다. 번역에서 인자의 순서를 바꾸거나 같은 인자를 반복하는 것은 허용한다. 변수에 저장한 리소스를 전달할 때는 `as const`로 리터럴 타입을 유지한다.

`shared/**/*.ts`는 서버·웹·리소스 타입 검사에 모두 포함되므로, 아직 앱에서 가져오지 않는 언어 파일도 검사한다. `npm run typecheck:i18n`은 리소스와 `tests/types/i18n.tsx`를 함께 검사하며, `npm run typecheck`와 `npm run build:web`에서도 실행한다. 빌드 중 타입 검사를 생략하는 Vite의 기본 동작에 의존하지 않는다.

`t`의 치환 값은 `string | number`이며, `null`·`undefined`·불리언은 호출 전에 처리한다. 키별 인자 누락·오타·불필요한 인자도 컴파일 오류다. React 요소와 조건부 내용은 `LocalizedMessage`로 전달하며, 이 경우에도 인자 이름은 검사한다. 동적 외부 키는 `isMessageKey` 또는 `isStaticMessageKey`로 확인한다.

## 유지하는 데이터

다음 값은 화면 문구와 구분해 유지한다.

- URL·API 경로, SQL, HTML/CSS 구조, SVG 경로, MIME·HTTP·인증·메일·캘린더 프로토콜 값.
- 상태·권한·역할 등의 식별자와 저장된 값. 표시할 때 `enumLabel` 또는 해당 화면의 메시지 매핑을 사용한다.
- 사용자가 작성한 이름·메일·일정·댓글, 저장된 역할 이름, 조직이 정의한 프로필 필드의 번역 데이터.
- 운영 로그, 파일 확장자·내보내기 파일 이름, 장식 기호·구분자, 브라우저 기본 컨트롤의 문구.

외부 서비스의 오류와 알 수 없는 외부 코드는 원래 값을 보존한다. 날짜·시간의 지역별 표시는 기존 캘린더 지역 형식 설정과 `Intl` 처리를 유지한다.

## 검증

```sh
npm run audit:ui-strings
npm run typecheck:i18n
npm run typecheck
npm test
```

AST 검사는 JSX 텍스트·도움말·접근성 속성, 옵션 레이블, 피드백·오류 문구, 동적 문장의 문자열을 확인한다. 프로토콜과 코드 문맥은 제외한다. 외부 응답이나 사용자 콘텐츠의 의미를 판별하는 검사는 아니므로, 새 UI에서는 동적으로 표시하는 코드에도 표시용 메시지 매핑을 추가한다.

`tests/i18n.test.mjs`는 값 치환, 단·복수, React 요소·이스케이프·조건부 내용, 상태 표시, 공개 페이지의 스크립트 구문, 하드코딩 문구 검사를 검증한다.

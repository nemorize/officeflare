# UI 문자열과 번역 리소스

애플리케이션의 UI 문자열을 조사하고, 화면에서 사용하는 문구를 `shared/i18n/en.ts`의 영문 메시지 4,114개로 분리했다. 미선택 언어 설정은 `system`이다. 동일한 영문이라도 문맥이 다르면 별도의 키를 유지한다.

한국어(`ko.ts`)와 일본어(`ja.ts`)도 각각 4,114개 키의 전체 번역을 제공한다. 두 파일은 영문 사전을 펼쳐 대체하지 않고 각 번역을 명시한다. 브랜드명, 프로토콜 식별자, URL과 단위는 보존한다. 계정의 환경설정(`/profile/preferences`) 페이지에서 시스템·영어·한국어·일본어를 선택하고 계정별로 저장한다. 시스템은 `navigator.languages`의 순서대로 지역 변형을 기본 언어에 연결하며, 지원 언어가 없으면 영어를 사용한다. 예를 들어 `fr-FR, ja-JP, en-US`는 일본어, `fr-FR, de-DE`는 영어가 된다.

## 파일과 사용법

- `shared/i18n/en.ts`: 메시지 원문. 키를 유지하면서 문구를 수정한다.
- `shared/i18n/ko.ts`, `shared/i18n/ja.ts`: 원문과 같은 키·치환 변수를 갖는 한국어·일본어 번역.
- `shared/i18n/locale.ts`: 지원 언어·선택값 타입, 브라우저 언어 결정, `Accept-Language` 파싱.
- `web/lib/browser-language.ts`: 브라우저 언어 적용과 HTML `lang`·제목·설명 갱신.
- `src/i18n.ts`: 동시 요청을 격리하는 서버 언어 컨텍스트.
- `shared/i18n/resource.ts`: 원문과 번역 리소스의 컴파일 단계 검증.
- `shared/i18n/index.ts`: 메시지 키·인자 타입, 이름이 있는 값 치환, 복수형 선택.
- `shared/i18n/labels.ts`: 상태·역할·작업 코드의 표시 문구.
- `web/components/i18n.tsx`: 링크·강조·조건부 요소를 유지하는 `LocalizedMessage`.
- `scripts/audit-ui-strings.mjs`: 하드코딩된 UI 문구의 재유입 검사.

```tsx
t("common.save");
t("workspace.navigation", { name: appName });
plural("counts.items", count);
enumLabel(account.status);

<LocalizedMessage
  id="workspace.navigation"
  values={{ name: <strong>{appName}</strong> }}
/>;
```

메시지는 `{name}` 형태의 인자를 사용한다. 문자열 인자는 한 번만 치환하고 HTML로 해석하지 않는다. 링크와 같은 React 요소는 `LocalizedMessage`로 전달한다. 수량에 따라 달라지는 문구는 `.one`과 `.other`에 명사·문장 전체를 저장한다.

환경설정의 언어 설정은 `PUT /api/me/language`로 `users.language`에 저장한다. 기존 계정의 기본값은 마이그레이션 `0024_user_language.sql`이 `system`으로 채운다. 이 변경은 인증 세션을 종료하거나 프로필 필드 정책에 의존하지 않는다. 적용되는 표시 언어가 달라지면 페이지를 새로 불러오며, 사용자에게 저장 전에 이를 안내한다. 브라우저 저장소에 언어 설정을 따로 복제하지 않는다.

`web/main.tsx`는 기존 `WorkspaceLoading` 로딩바 화면에서 세션 복원과 계정 언어 확인을 처리한 후 `web/app.tsx`를 가져온다. 초기 로딩과 앱은 같은 React 루트를 공유하고, 세션 시작은 한 번만 실행한다. 따라서 모듈 초기화 시 만들어지는 메뉴·옵션·편집기 문구도 선택한 언어를 사용한다. 로그아웃하면 시스템 설정으로 돌아가고, 시스템 모드의 `languagechange` 이벤트도 반영한다. 계정 설정은 다른 기기에도 적용되며, 다른 탭은 기존 세션 동기화(포커스·온라인 복귀 등)에서 최신 값을 받는다.

API 요청은 적용된 언어를 `Accept-Language`에 담는다. Worker는 `AsyncLocalStorage`로 요청별 언어를 격리하고 API 오류·권한 설명·제공업체 설정·알림 종류·공개 캘린더 페이지에 적용한다. 비요청 작업의 기본값은 영어이며, 이미 저장된 알림 본문과 사용자 콘텐츠는 자동 재번역하지 않는다. 캘린더의 별도 지역 형식 설정은 계속 날짜 표시를 제어한다.

정적 `index.html`의 `{{i18n:...}}` 표시는 Vite가 개발·빌드 시 영문 메시지로 치환한다. 공개 캘린더 페이지는 같은 리소스를 사용하며, HTML 텍스트와 브라우저 스크립트에 맞게 각각 이스케이프한다. CSS 선택자는 번역되는 접근성 레이블에 의존하지 않는다.

## 리소스 타입 검사

영문 원문은 `defineMessages({...})`로 선언한다. 값은 리터럴 문자열이어야 하며, `{name}`의 이름은 영문·숫자·밑줄로 구성하고 숫자로 시작하지 않는다. 닫히지 않은 괄호·중첩된 괄호·빈 인자는 컴파일 오류다. `.one`과 `.other`는 짝을 이루고 같은 인자를 사용해야 하며, 두 문장 모두 `{count}`를 포함한다. `labels.*`는 인자가 없는 문구만 허용한다.

다른 언어 파일은 원문을 기준으로 `defineTranslations(en, {...})`로 선언한다.

```ts
import { defineMessages, defineTranslations } from "./resource.ts";

const source = defineMessages({
  "common.save": "Save",
  "workspace.navigation": "{name} navigation",
});

const ko = defineTranslations(source, {
  "common.save": "저장",
  "workspace.navigation": "{name} 탐색",
});
```

위 예제는 작은 원문 사전 전체를 번역한다. 실제 언어 파일은 `en`을 기준으로 모든 키를 작성한다. 누락·추가된 키, 문자열 이외의 값, 잘못된 메시지 형식, 누락·추가·변경된 인자는 컴파일 오류다. 번역에서 인자의 순서를 바꾸거나 같은 인자를 반복하는 것은 허용한다. 변수에 저장한 리소스를 전달할 때는 `as const`로 리터럴 타입을 유지한다. 한국어와 일본어도 `.one`과 `.other`를 모두 유지하며, 수량에 따라 문구가 바뀌지 않으면 같은 번역을 사용한다.

`shared/**/*.ts`는 서버·웹·리소스 타입 검사에 모두 포함되므로, 아직 앱에서 가져오지 않는 언어 파일도 검사한다. `npm run typecheck:i18n`은 리소스와 `tests/types/i18n.tsx`를 함께 검사하며, `npm run typecheck`와 `npm run build:web`에서도 실행한다. 빌드 중 타입 검사를 생략하는 Vite의 기본 동작에 의존하지 않는다.

`t`의 치환 값은 `string | number`이며, `null`·`undefined`·불리언은 호출 전에 처리한다. 키별 인자 누락·오타·불필요한 인자도 컴파일 오류다. React 요소와 조건부 내용은 `LocalizedMessage`로 전달하며, 이 경우에도 인자 이름은 검사한다. 동적 외부 키는 `isMessageKey` 또는 `isStaticMessageKey`로 확인한다.

## 유지하는 데이터

다음 값은 화면 문구와 구분해 유지한다.

- URL·API 경로, SQL, HTML/CSS 구조, SVG 경로, MIME·HTTP·인증·메일·캘린더 프로토콜 값.
- 상태·권한·역할 등의 식별자와 저장된 값. 표시할 때 `enumLabel` 또는 해당 화면의 메시지 매핑을 사용한다.
- 사용자가 작성한 이름·메일·일정·댓글, 저장된 역할 이름, 조직이 정의한 프로필 필드의 번역 데이터.
- 운영 로그, 파일 확장자·내보내기 파일 이름, 장식 기호·구분자, 브라우저 기본 컨트롤의 문구.

외부 서비스의 오류와 알 수 없는 외부 코드는 원래 값을 보존한다. 날짜·시간의 지역별 표시는 기존 캘린더 지역 형식 설정과 `Intl` 처리를 유지한다.

## 검증

```sh
npm run audit:ui-strings
npm run typecheck:i18n
npm run typecheck
npm test
```

`tests/language.test.mjs`와 `tests/request-language.test.mjs`는 언어 결정·적용, 복수형·리치 콘텐츠, API 언어 전달, 비동기 요청 격리를 검증한다. 계정 API 테스트는 기본값, 영속성, 허용값 검증, 다른 계정 보호와 세션 유지를 확인한다.

AST 검사는 JSX 텍스트·도움말·접근성 속성, 옵션 레이블, 피드백·오류 문구, 동적 문장의 문자열을 확인한다. 프로토콜과 코드 문맥은 제외한다. 외부 응답이나 사용자 콘텐츠의 의미를 판별하는 검사는 아니므로, 새 UI에서는 동적으로 표시하는 코드에도 표시용 메시지 매핑을 추가한다.

`tests/i18n.test.mjs`는 전체 번역의 키·치환 변수 일치, 문맥별 번역과 프로토콜 값 보존, 값 치환, 단·복수, React 요소·이스케이프·조건부 내용, 상태 표시, 공개 페이지의 스크립트 구문, 하드코딩 문구 검사를 검증한다.

# 메일 이미지 사전 처리

신규 수신 및 EML/MBOX 가져오기는 메시지를 게시하기 전에 서버에서 외부 스타일시트와 이미지, CID 첨부 이미지를 처리합니다. 검증된 이미지는 본문 리비전별 R2 객체(`bodies/...json.render-v1.json`)에 저장됩니다. 화면은 서버에서 이미지를 삽입한 HTML을 한 번 요청하며 이미지별 다운로드·Base64 변환을 수행하지 않습니다. 원본 메일과 첨부 파일은 그대로 보존합니다.

`MAIL_RENDER_ORIGIN`은 서비스의 HTTPS origin으로 설정합니다. 서버의 이미지 프록시가 애플리케이션 자체를 요청하지 않도록 사용합니다. 기존의 공개 DNS 검증, 리다이렉트 검증, SVG 정제, 이미지당 5 MiB 제한을 유지하며, 메일당 최대 96개·20 MiB, 최대 4개 동시 처리와 12초 처리 시간을 적용합니다. 접근 권한과 본문 리비전은 응답 직전에도 다시 확인합니다. 영구 삭제 시 기존 본문 정리 작업이 렌더링 객체도 삭제합니다.

이미지나 스타일시트가 실패하면 정상 처리된 이미지와 본문을 저장하고 실패 개수를 함께 반환합니다. 일반 열람은 저장된 결과를 사용하고, 화면의 다시 시도로 실패한 리소스를 다시 처리합니다.

## 기존 메일 처리

처리 결과가 없는 기존 메일은 사용자가 본문을 처음 열 때 `GET /api/mail/mailboxes/:mailbox/messages/:message/render` 요청에서 서버가 이미지를 내려받고 검증·변환한 결과를 R2에 저장합니다. 첫 응답부터 이미지가 삽입된 HTML을 반환하므로 클라이언트에서 이미지를 개별 처리하지 않습니다.

이후 열람은 저장된 결과를 재사용합니다. 임시 Cache API 항목이 만료되거나 다른 지역에서 조회해도 이미지를 다시 내려받지 않습니다. 본문 리비전이 변경되면 새 리비전에 대한 결과를 별도로 준비합니다. 원본 본문과 첨부 파일은 유지합니다.

메일 목록 조회는 이미지 처리를 실행하지 않습니다. 본문을 열 권한이 있는 요청에서만 처리하며, 일부 이미지가 실패해도 본문과 정상 이미지를 표시할 수 있습니다. 다시 시도는 `retry=1`로 실패한 리소스만 재처리합니다.

기존 메일 처리를 위한 별도 마이그레이션 실행이나 API 키 설정은 필요하지 않습니다. 빌드·배포 준비 단계에서도 메일을 일괄 처리하지 않습니다.
